# 中控屏自动读取的数据与隐私说明

桥接程序在中控屏本机读取厂商应用已有的数据，自动取得连接 IHG2 网关和生成 Apple 家庭配件清单所需的信息。网关密钥、网关地址和配件清单不需要输入，也不会复制到维护电脑。

| 数据项 | 来源 | 当前核验结果 |
| --- | --- | --- |
| 网关 AES 密钥 | 厂商应用 cn.net.cloudthink.smartmirror 的 app_gatewaysdk/config.db，字段 ihgAeskey | 32 位十六进制，即 16 字节 AES-128 密钥；桥接协议使用 AES-128-CBC。程序不打印密钥，也不通过 ADB 传到维护电脑。 |
| 网关 MAC 地址 | 同一 config.db 的 ihgMac 字段 | 与当前中控屏和网关的身份信息一致。 |
| 网关 IP 地址 | 中控屏 /proc/net/arp 邻居表中与网关 MAC 对应的记录 | 当前中控屏可自动解析。程序不要求手工保存 IP；若邻居表尚无记录，先用厂商应用连接网关，再重新安装或运行诊断。 |
| 网关 UDP 端口 | 屏端协议参数 | 当前已核验为 80。 |
| 协议设备 ID 和类型 | 屏端协议参数 | 当前中控屏使用设备 ID 1，报文类型为 0x274a。这些是固件协议参数，不是每户单独配置。 |
| 配件清单、名称、平台、通道和属性 | 厂商 SDK 的 subdevs.db 及其中的 vgroups | 当前样本由 48 条屏端记录自动生成 31 个桥接配件，与当前桥接清单逐项一致。该清单由厂商应用同步维护。 |
| HomeKit 桥名称和端口 | 桥接程序默认值 | 自动使用 IHG2 Local Bridge 和 TCP 端口 53760，不从网关读取。 |
| HomeKit 配对身份 | 中控屏上的 .hap_store | 首次运行时自动生成并保存；升级时保留现有配对。安装后仍需在 Apple 家庭中完成一次添加配件。 |
| 可选门锁 Wi-Fi 在线传感器 | 每户单独写入中控屏的 config/lock-sensor.conf | 需要手动提供该户门锁 IP 和 Wi-Fi MAC。只探测指定 IP 并校验 MAC，不扫描网段。它表示局域网可达，不代表门锁已解锁。 |

## 每户配置如何隔离

兼容的家庭使用同一份软件发布包。每户的 AES 密钥、网关地址和配件清单都在该户中控屏运行时读取，不编译进程序，也不写入安装包。桥接程序以只读方式访问厂商 SDK 数据库，不修改厂商数据库。

这些 SDK 数据库位于 Android 应用私有目录，通常只有厂商应用自身可读；本桥以 root 身份运行，因此可以读取。程序只提取连接网关、控制配件和建立 HomeKit 配件所需的字段，不导出云端令牌、授权信息或场景数据。场景编辑和场景执行不属于本桥接服务的功能。

门锁 Wi-Fi 在线传感器是唯一需要按家庭手动配置的可选项。配置命令通过 ADB 在中控屏写入该户自己的 root 私有文件；以后门锁 IP 变化时重新执行命令即可，不需要重新编译或重启。

## 兼容性边界

当前实机核验覆盖一台 RK3288 中控屏及其厂商应用版本。其他家庭的中控屏即使版本号相近，也应先运行发布包中的 Doctor，确认 root、SDK 数据、配件数量、网关心跳、HomeKit 监听和启动钩子均正常。

桥接程序最多支持 32 个配件。若设备数量超过上限，或者厂商应用更改数据库结构，程序会拒绝启动并报告检查失败，不会静默生成不完整的配件列表。发现新的设备类别时，需要更新桥接程序并重新构建发布包；同一软件版本仍可供所有兼容家庭使用，不需要按家庭分别编译。

Doctor 命令在健康检查通过后会显示首次添加 Apple 家庭所需的 HomeKit 配对码。它不会显示网关密钥、地址、MAC、设备名称或设备标识；配对码属于家庭凭据，应避免公开分享。

维护电脑上的 Doctor 命令示例：

    Linux：./install.sh PANEL_IP --doctor
    Windows：.\install.cmd PANEL_IP -Doctor

Doctor 只发送一个用于连通性检查的网关心跳，不发送开关、窗帘或空调控制命令。
